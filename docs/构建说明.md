# 构建说明

## 版本来源

本仓库从现有 `OP13HyperOSFix` 工程独立复制，保留 `1.58.0-coloros-wallet`，versionCode 75。没有采用先前找到的 1.56.3 备份，没有删除钱包修复，没有更改现有 Hook 逻辑。

为方便换电脑编译，补充了根目录 Gradle Wrapper、分发包校验值、Git 忽略规则和中文说明。原工作工程保持不动。

## 准备环境

| 组件 | 版本 |
| --- | --- |
| JDK | 17 |
| Gradle | 9.3.1，由 Wrapper 下载 |
| Android Gradle Plugin | 9.1.1 |
| Kotlin Compose 插件 | 2.3.10 |
| compileSdk / targetSdk | 37 |
| minSdk | 35 |
| Build Tools | 由 AGP 选择，允许 SDK 管理器安装所需版本 |
| NDK | 28.2.13676358 |
| APK ABI | arm64-v8a |
| Xposed API | 82 |

在 Android Studio 的 SDK 管理器安装上述 SDK、Build Tools 和 NDK。`JAVA_HOME` 指向 JDK 根目录，`ANDROID_HOME` 指向 SDK 根目录。

也可以在本地 `local.properties` 里设置 `sdk.dir`，推荐用正斜杠路径。这个文件只用于本机，不提交 Git。

```properties
sdk.dir=C:/Android/Sdk
```

Gradle Wrapper 使用官方分发地址，并固定 SHA-256：

```text
b266d5ff6b90eada6dc3b20cb090e3731302e553a27c5d3e4df1f0d76beaff06
```

## 开始编译

Windows PowerShell：

```powershell
$env:JAVA_HOME = 'C:\Java\jdk-17'
$env:ANDROID_HOME = 'C:\Android\Sdk'
.\gradlew.bat :app:assembleRelease --no-daemon
```

上面的路径按本机安装位置调整。Linux 和 macOS 配置对应环境变量后运行：

```bash
./gradlew :app:assembleRelease --no-daemon
```

编译结果在 `app/build/outputs/apk/release/app-release.apk`。构建警告与构建失败需要区分，以退出码和最后的 `BUILD SUCCESSFUL` 为准。

## 必须保留的文件

不能为了清理仓库把下面的二进制文件全忽略掉，它们是本版本的构建或运行输入。

- `gradle/wrapper/gradle-wrapper.jar`
- `app/libs/dexkit-2.2.0.aar`
- `app/libs/flatbuffers-java-23.5.26.jar`
- `app/libs/hidden-api-stubs.jar`，仅编译时使用
- `app/src/main/jniLibs/arm64-v8a/` 内的 LHDC 库
- `app/src/main/assets/` 内的辅助程序、内核模块、RTP、音乐和规则
- `app/src/main/res/raw/` 内的预编译采样程序和其他资源

不需要上传 Android SDK、NDK、JDK、Gradle 缓存、编译输出、`local.properties` 和签名私钥。

## 原生代码与内核模块

标准 APK 构建按 `app/src/main/cpp/Android.mk` 编译 `libop13_lhdc_patch.so`。并非所有 C 文件都自动参与这一步。

`native-src`、`kernel-src` 和上游触感工程保存了现有源码，APK 直接打包相应预编译程序。重新编译 KO 需要目标内核的源码、配置、符号和工具链，不能只凭同一个 6.6 主版本就认定所有内核兼容。

仓库保留现有 LTPO 等预编译依赖，不宣称附带每个厂商二进制的完整源码。只编译 APK 时不需要重新生成这些文件。

## 签名和测试边界

Release 仍沿用工程原有的 debug 签名配置，没有随本次整理更换签名方式。不同电脑的 debug 密钥可能不同，覆盖安装可能提示签名不一致。

本次整理验证的是从独立目录编译，不代表所有 Hook 已在每种 OTA 上验证。没有安装到手机，也没有重启手机。原修复记录中的实机结论对应当时测试系统，不可直接推断新 ROM 一定兼容。
